“AI로 게임 만든다”는 문장은 매력적이다.
그런데 열어보면 선택지가 한꺼번에 쏟아진다. 엔진, 언어, 아트, 사운드, 스토리, 빌드, 스토어…

오늘은 기초부터 필요한 것만 순서대로 남긴다.
도구 카탈로그가 아니라, 혼자(또는 소수) + AI로 첫 플레이 가능한 조각을 만들기 위한 체크리스트다.

전제: AI는 엔진이 아니다

AI는 코드를 짜 주고, 스프라이트를 그려 주고, 대사를 써 준다.
하지만 게임이 재미있는지는 플레이 루프를 돌려 봐야 안다.

그래서 순서를 이렇게 잡는다.

순서 질문 의미
1 무엇을 만들지 범위
2 어디에 만들지 엔진
3 무엇을 AI에게 맡길지 역할 분담
4 한 판이 도는지 수직 슬라이스

도구를 먼저 모으면, 프롬프트만 쌓이고 실행 파일이 안 나온다.

1) 범위를 먼저 자른다

첫 작품은 AAA가 아니라 한 가지 재미다.

범위 예시 AI와 잘 맞는 이유
마이크로 10초 클리커, 1화면 피하기 루프가 짧아 피드백이 빠름
미니 3스테이지 플랫포머, 간단한 퍼즐 에셋·로직 양이 감당 가능
피하기 오픈월드, 멀티, 라이브 서비스 요구사항이 AI 출력을 삼킴

정의할 것 네 줄이면 충분하다.

항목 적어 둘 질문
행동 플레이어는 무엇을 하는가
승패 이기거나 지는 조건은 무엇인가
화면 화면은 몇 장인가
끝 “끝”은 언제인가

이 네 줄이 모호하면, AI에게 “멋진 게임 만들어줘”를 쳐도 멋진 잡음만 돌아온다.

2) 엔진·언어 — 하나를 고르고 고정한다

초보 + AI 조합에서 많이 쓰는 축이다.

선택 감각 언제
Godot (GDScript) 가볍고 2D에 친절 혼자, 2D, 학습 곡선 낮게
Unity (C#) 자료·에셋 스토어가 큼 3D·모바일·레퍼런스 많을 때
웹 (HTML Canvas / Phaser) 배포가 즉시 프로토타입·공유가 목표면
Python (pygame 등) 문법이 익숙 “게임다움”보다 로직 실험

중요한 건 매주 엔진을 바꾸지 않는 것이다.
AI는 컨텍스트가 흔들리면 어제 코드와 다른 API를 섞어 넣는다.
엔진 하나, 버전 하나, 프로젝트 폴더 하나를 고정하자.

로컬에 필요한 최소 세트:

준비물 역할
엔진 설치 + 빈 프로젝트 실행·씬의 집
Git (또는 zip 백업) 깨져도 되돌리기
코드 에디터 (VS Code / Cursor 등) 스크립트 편집
AI 채팅 또는 에이전트 코드·문서 보조

3) AI에게 맡길 일 / 내가 맡을 일

역할을 나누면 프롬프트가 짧아진다.

구분 내용
AI가 잘 하는 쪽 스캐폴딩(이동·충돌·씬 전환)
보일러플레이트(UI·세이브·빌드 설명)
에셋 초안(타일·아이콘·효과음 아이디어)
리팩터·버그 원인 후보 정리
내가 붙잡을 쪽 재미의 기준(점프 감·난이도)
이번 버전에 넣지 않을 기능 거절
플레이 테스트 로그
라이선스·스토어 정책 확인

한 줄로 말하면, AI는 제작 보조, 디렉터는 나다.

4) 에셋·사운드 — 완성도보다 읽히는 형태

픽셀 아트가 없어도 된다. 처음엔 도형 + 색으로도 루프를 검증할 수 있다.

그래도 AI/생성 툴을 쓸 때 최소 규칙:

규칙 이유
스타일 키워드 고정
(예: 16×16, top-down, limited palette)		 에셋이 서로 안 어울리는 걸 줄임
캐릭터·맵·UI를 한 번에 시키지 않기 품질·일관성이 떨어지기 쉬움
생성물은 임시, 루프 굳은 뒤 교체 재미 검증이 먼저
상용·학습용 라이선스 구분 배포 시 사고 방지

사운드도 같다. 무음 프로토타입 → 클릭/히트 효과 몇 개 → BGM은 나중.

5) 프롬프트는 스펙처럼 쓴다

막연한 요청 대신, 재현 가능한 지시가 낫다.

나쁜 예 나은 예
재미있는 플랫포머 만들어줘. Godot 4, 2D.
플레이어는 좌우 이동·점프.
바닥·가시는 StaticBody2D.
가시에 닿으면 시작 위치로.
스크립트 + 노드 트리까지 적어줘.

추가로 습관화할 것:

습관 효과
현재 파일/에러 로그를 붙여 디버깅 추측성 수정 감소
새 기능 전에 “기존 동작 유지” 명시 회귀 버그 감소
한 대화에서 엔진 바꾸지 않기 API 혼선 방지
생성 코드는 한 번 실행 후 다음 요청 검증 속도 = 진행 속도

AI 게임 개발의 병목은 생성 속도가 아니라 검증 속도다.

6) 첫 마일스톤: 수직 슬라이스

거창한 로드맵 대신, 이 상태가 되면 1단계 통과다.

# 통과 조건
1 실행하면 창이 뜬다
2 입력이 캐릭터에 반영된다
3 실패/성공이 한 번이라도 판정된다
4 다시 시작할 수 있다

여기까지가 수직 슬라이스다.
맵 열 장, 스킬 트리, 인벤토리는 그 다음 커밋이다.

손에 남길 최소 세트

# 최소 세트
1 한 줄 컨셉 + 승패 조건
2 엔진 하나 고정
3 Git/백업
4 AI = 코딩·에셋 초안 / 나 = 범위·재미·테스트
5 수직 슬라이스까지 반복

완벽한 툴체인을 기다리지 않아도 된다.
플레이 가능한 한 판이 생기면, 그때부터가 진짜 게임 디버깅이다.

참고: 엔진·생성형 툴·스토어 정책은 자주 바뀐다. 이 글은 2026년 기준의 입문 순서 메모이며, 특정 엔진/모델의 공식 튜토리얼을 대체하지 않는다.
